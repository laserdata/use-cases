Setup

Cluster
LaserData Cloud, Standard tier, Large compute (4 vCPU, 15.6 GiB RAM per node), 3-node cluster with replication, GCP us-central1, single zone, 100 GB network drive per node, $1,051/month base. Iggy v0.10.3.
Settings
As deployed: memory pool 4 GiB, no partition cap, per-stream rate limits off (unlimited).
Client
One Google Cloud VM, n2-standard-8, us-central1-a (same region), Laser SDK 0.9.1 for Python. Access rule open to this VM's IP only.
Backlog test
One writer paced at 15,000 records/s writes 7,000,000 records (1 KiB, batches of 100) to a fresh stream with nobody reading; then one fresh consumer with the SDK's default settings reads all of them from the first offset. Every record carries its sequence number, so missing and duplicate records are counted. The stream is deleted afterwards.
Order
One test at a time; the console must show 3 of 3 nodes serving and 0 under-replicated partitions before the next one starts.
Measured
Client memory and CPU from /proc once a second; send times and record counts in the client; node health, memory and CPU from the LaserData console.

Earlier: a Small cluster (15 Nov)

Before this run, the same tests were tried on a Small cluster (2 vCPU per node, $199/month). The ramp-up held 20,000/s and a 10-partition backlog of 5M records read in a flat 72 MiB, but at 50 partitions that cluster lost quorum and did not recover. Those results are not used here.
